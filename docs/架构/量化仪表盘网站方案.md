## 三、集成到博客的方案对比

你的博客是 Next.js App Router，路径 `/Users/xoln/Desktop/编程/博客/site`。

### 方案A：iframe 嵌入（最快，5分钟）

```
博客项目:
  public/quant/
    ├── index.html          (仪表盘HTML)
    └── data.json           (数据文件, cron自动更新)

  src/app/works/quant/page.tsx:
    export default function QuantPage() {
      return <iframe src="/quant/index.html" style={{width:'100%', height:'100vh'}} />
    }
```

| 优点 | 缺点 |
|------|------|
| 零代码改动 | 风格独立，不跟随博客主题 |
| 5分钟搞定 | iframe 在移动端体验一般 |
| 数据更新方便（cron覆盖文件） | 无法与博客其他部分联动 |

### 方案B：React 组件渲染（更好，2-3小时）

```
博客项目:
  src/app/works/quant/
    ├── page.tsx            (仪表盘首页)
    ├── backtest/page.tsx   (回测详情)
    ├── signals/page.tsx    (信号历史)
    ├── factors/page.tsx    (因子分析)
    └── data/page.tsx       (数据监控)

  public/quant/data.json    (数据文件, cron更新)

  组件库:
    ├── MarketCard.tsx       (市场状态)
    ├── HealthCard.tsx       (数据健康)
    ├── StrategyChart.tsx    (策略图表)
    ├── PositionList.tsx     (持仓列表)
    ├── SignalTable.tsx      (信号表格)
    └── FactorTable.tsx      (因子排名)
```

| 优点 | 缺点 |
|------|------|
| 风格跟随博客主题 | 需要写 React 组件 |
| 路由自然，SEO友好 | 数据更新仍需 cron |
| 可以加交互（筛选、搜索） | 开发时间较长 |
| 可以复用博客的布局/导航 | |

### 方案C：混合方案（推荐，1小时）

```
Phase 1 (现在): 方案A — iframe 嵌入，立即可用
Phase 2 (后续): 逐页迁移到方案B — 先迁移仪表盘首页，其他页面继续用HTML
Phase 3 (最终): 全部 React 组件化
```


### 服务器（部署后）

```bash

30 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python scripts/generate_dashboard_data.py

# 如果集成到博客（方案A）：
# 数据生成后自动复制到博客 public 目录
30 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python scripts/generate_dashboard_data.py && cp dashboard/data.json /path/to/blog/public/quant/
```

### 全自动（理想状态）

```
cron 21:00  run.py (下载数据+生成信号+推钉钉)
cron 21:05  report.py (市场日报)
cron 21:10  health_check.py (健康检查)
cron 21:15  health_check.py --backup (数据库备份)
cron 21:30  generate_dashboard_data.py (更新仪表盘数据)  ← 新增
```
