## 第四步：创建 Token 配置文件

这是最关键的一步——token 文件不会被 git 同步，必须在服务器上手动创建。

**步骤 4.1**：先检查文件是否已存在：

```bash
cat /root/Liang-Hua/config/settings_local.py 2>/dev/null && echo "文件已存在" || echo "文件不存在，需要创建"
```

**步骤 4.2**：如果"文件不存在"，执行以下命令创建（**把你的真实 token 替换进去**）：

```bash
cat > /root/Liang-Hua/config/settings_local.py << 'EOF'
# 服务器敏感配置
DINGTALK_WEBHOOK = "https://oapi.dingtalk.com/robot/send?access_token=a3b39c84f4c6d57f075e993525835691056200eb8558cc2fe103867413570883"
TUSHARE_TOKEN = "f4273b569effee2274406ba3651f0506e34890334c73e20e1a296dad"
BARK_KEY = ""
EOF
```

> ⚠️ **上面两行 token 必须换成你的真实值！** DINGTALK_WEBHOOK 是在钉钉机器人管理页面拿到的，TUSHARE_TOKEN 是在 tushare.pro 个人中心拿到的。

**步骤 4.3**：确认文件内容正确：

```bash
cat /root/Liang-Hua/config/settings_local.py
```

**预期输出**：能看到你的 token 值（不是"替换为实际"这种占位符）。

**步骤 4.4**：确认 token 能正常加载：

```bash
cd /root/Liang-Hua && ./venv/bin/python -c "
from config import settings
print('DINGTALK: ' + ('✅ 已配置' if len(settings.DINGTALK_WEBHOOK) > 10 else '❌ 为空！'))
print('TUSHARE:  ' + ('✅ 已配置' if len(settings.TUSHARE_TOKEN) > 10 else '❌ 为空！'))
"
```

**预期输出**：

```
DINGTALK: ✅ 已配置
TUSHARE:  ✅ 已配置
```

如果显示 ❌，说明第四步没做对，回到步骤 4.2 重新创建文件。

## 第五步：更新 Crontab 定时任务

**步骤 5.1**：查看当前 crontab：

```bash
crontab -l
```

**预期输出**：能看到旧的 2 条定时任务（也可能为空）。

**步骤 5.2**：编辑 crontab：

```bash
crontab -e
```

这会打开一个文本编辑器（通常是 vi）。**按下面步骤操作**：

1. 按 `i` 键（进入编辑模式，左下角出现 `-- INSERT --`）
2. 用方向键移到文件末尾
3. 如果已有旧的定时任务，**全部删掉**（按方向键到那一行，按 `dd` 删除整行）
4. 粘贴以下 5 行（**在终端里用 Cmd+V 粘贴**）：

```
# 量化交易系统定时任务
0 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python run.py >> logs/cron.log 2>&1
5 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python analysis/report.py >> logs/report.log 2>&1
10 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python scripts/health_check.py >> logs/health.log 2>&1
15 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python scripts/health_check.py --backup >> logs/health.log 2>&1
20 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python web/generate.py >> logs/dashboard.log 2>&1 && coscmd upload -r web/output/ /quant/ --delete >> logs/dashboard.log 2>&1
```

5. 检查内容无误后，按 `Esc` 键（退出编辑模式）
6. 输入 `:wq` 然后按回车（保存并退出）

**步骤 5.3**：确认 crontab 已更新：

```bash
crontab -l
```

**预期输出**：看到 4 行定时任务，跟上面粘贴的一模一样。

> ⚠️ 如果 crontab -e 打开的不是 vi 而是 nano：操作更简单——直接粘贴内容，然后 `Ctrl+X` → `Y` → 回车。

## 第七步半：配置 COS 上传（仪表盘自动发布到博客）

仪表盘是纯静态 HTML，每天生成后自动上传到 COS，通过博客域名 `xoln.me/quant` 访问，不需要 rebuild 博客。

**步骤 7.5.1**：安装 coscmd：

```bash
pip install coscmd
```

**步骤 7.5.2**：配置 coscmd（需要 COS 密钥）：

```bash
coscmd config -a <你的SecretId> -s <你的SecretKey> -b xolnxoln-1431302682 -r ap-guangzhou
```

**步骤 7.5.3**：测试上传：

```bash
cd /root/Liang-Hua
./venv/bin/python web/generate.py
coscmd upload -r web/output/ /quant/ --delete
```

**预期输出**：看到文件列表逐一上传，末尾无报错。

**步骤 7.5.4**：测试是否能通过博客域名访问：

```bash
curl -sI https://xoln.me/quant/index.html | head -3
```

**预期输出**：

```
HTTP/2 200
content-type: text/html
```

如果返回 404，说明 CDN 缓存还没刷新——到腾讯云 CDN 控制台手动刷新 `/quant/` 路径。

> 以后每天 21:20 自动执行 web/generate.py + coscmd upload，无需手动操作。

## 与旧版的关键差异

| 项目       | 旧版                        | 新版                                |
| ---------- | --------------------------- | ----------------------------------- |
| Token 存放 | `settings.py`（Git 公开） | `settings_local.py`（服务器独有） |
| 定时任务   | 2 条                        | 5 条（多了健康检查+备份+仪表盘）    |

| 崩溃通知   | 崩了不知道                  | 21:10 自动钉钉告警                  |
| 仪表盘     | 无                          | 每天生成 + COS 自动上传到博客       |
| 博客集成   | 无                          | `xoln.me/quant` 实时查看信号      |
