# 信号效果验证系统说明

> 2026-08-16 交付 · 设计：`docs/superpowers/specs/2026-08-16-signal-outcome-design.md` · 实施计划：`docs/superpowers/plans/2026-08-16-signal-outcome.md`

## 系统是什么

回答一个问题：**钉钉推的这些信号到底有没有用？**

对每条交易信号自动检验其"预测力"（L1）和"完整买卖周期的收益"（L2），结果持续累积在数据库，展示在仪表盘「信号效果」页。为策略打磨提供数据依据——改完策略参数，一周后命中率变化立即可见。

**两种口径**：

| 口径 | 回答的问题 | 周期 | 成本假设 |
|---|---|---|---|
| L1 固定窗口 | 信号发出后股票跑赢/跑输大盘没有 | 信号后 5/10/20 个交易日（固定，可比） | 无手续费（纯预测力） |
| L2 等权账本 | 按"买入→卖出信号/止损/到期"完整周期赚不赚钱 | 持仓自然周期（规则决定） | 信号次日开盘价成交 |

**用户决策**（设计讨论确认）：L1+L2 都做；样本以历史回放为主、真实信号持续累积；持续跟踪系统（非一次性分析）；L2 等权无视资金（检验信号纯度，不受仓位分配干扰）；结果在仪表盘展示。

## 运行方式

```bash
# 每日增量结算（服务器 cron 21:02 自动，也可手动）
python scripts/signal_outcome.py

# 首次部署补齐历史 / 重跑刷新（约 5-6 分钟，全量重算后覆盖 replay 数据）
python scripts/signal_outcome.py --replay

# 服务器 cron（setup.sh 打印建议，需手动 crontab -e）
2 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python scripts/signal_outcome.py >> logs/signal_outcome.log 2>&1
```

每日流程：21:00 run.py 出信号 → 21:02 signal_outcome 结算（L1 窗口到期 + L2 持仓推进）→ 21:20 仪表盘更新。

## 数据表（signal_outcome，schema v3）

```
UNIQUE(date, code, strategy, action, kind, source, exit_reason, open_date)
```

| kind | 含义 | 说明 |
|---|---|---|
| `l1_5d` / `l1_10d` / `l1_20d` | L1 窗口结算 | pnl=窗口收益%，excess=对沪深300超额% |
| `l2_open` | L2 开仓事件 | 次日开盘成交，exec_price=成交价 |
| `l2_close` | L2 平仓事件 | exit_reason='sell'/'stop_loss'/'timeout' |
| `l2_state` | 每日状态快照（单行 JSON） | date=状态水印；负载含 positions/pending/**processed**（已登记信号键，补登记幂等权威依据） |

- `source`：`'real'`（真实钉钉信号）/ `'replay'`（回放补齐）——两套账本互不干扰
- schema 迁移：v1→v3 由 `_migrate_outcome_schema()` 自动重建（保留全部行），每日结算/回放入口都会检查
- 幂等：L1 用 INSERT OR IGNORE；replay 重跑 = **先清后算**（DELETE source='replay' 后全量重算，行数必然与首跑一致——v3 键含 open_date 后旧行与新行键不同，不能依赖 IGNORE 去重）

## L1 语义（页面解读口径）

- 收益 = 第 N 交易日收盘 / 信号日收盘 − 1；超额 = 收益 − 同期沪深300
- 命中判定：**BUY 超额 > 0 命中；SELL 超额 < 0 命中**（反向验证——卖出信号后跌 = 信号对）
- 页面 L1 表按 BUY/SELL **拆行**：SELL 行的"平均超额"列已**翻转符号**展示（正数 = 回避的跌幅 = 好），表头有注记——不要与 BUY 行口径混读
- 窗口不足 N 交易日 → 不结算等后续（每日自动补）；停牌/退市无行情 → **放弃该样本不落行**

## L2 语义（页面解读口径）

- 每个 BUY 等权 1 份，信号日收盘产生 → **次日开盘价成交**（与 21:00 收信号、次日 9:30 下单一致）
- 平仓三因：SELL 信号（FIFO 配对）/ 移动止损（持仓期峰值回落 5%，Ledger 自算）/ 60 交易日到期
- 无持仓的 SELL 不执行；同股多笔先进先出
- **止损归属不对称（解读注意）**：real 账本里生产"移动止损"SELL 落 `exit_reason='sell'`（真实信号就是卖出指令），replay 账本里止损由 Ledger 自算落 `'stop_loss'`——同为"止损离场"，两账本落码不同，统计止损有效性时需知道此口径
- 不模拟：资金约束/手续费/滑点/一字板买不进 → 收益偏乐观，作为**策略间对比的相对值**使用

## 仪表盘页面

导航「效果」→ 三个 tab：
- **合并**（默认）：real + replay 合看，表头注来源构成（重叠期样本双计，两源各自独立）
- **真实信号**：只看钉钉实际发的（样本少但最真实——验证"我收到的信号准不准"）
- **回放历史**：只看回放补齐的（样本足，统计检验用）

页面内容：L1 命中率表（策略×方向×胜率×平均超额 ✅/❓/⚠️）→ L2 等权账本表（笔数/胜率/平均收益/平均持仓/等权累计）→ 最近结算列表。

**初版范围（有意决策，待二期）**：L1 仅展示 10 日窗口（5/20 日照常入库不展示）；L2 无"止损统计面板"；样本 <30 无"样本不足"提示（小样本解读需自行留意）。

## 已知局限（如实记录）

| 局限 | 影响 |
|---|---|
| qfq 前复权在 1 年回放内失真小但存在 | 回放窗口=REPLAY_YEARS=1 年是有意控制 |
| 当前成分股回看历史（幸存者偏差）| 与现有回测同源；is_st 亦取当前状态过滤历史 |
| 无滑点/手续费模拟 | L2 收益偏乐观，只作相对对比 |
| 回放不含大盘择时降权 | v3 择时只调 strength 排序，等权验证不受影响 |
| 回放窗口尾部持仓无平仓样本 | 批处理固有边界；滚动重跑窗口前移时自然收敛 |
| cron 漏跑 | catch-up 逐日补齐；状态日当天的晚到信号会补登记（成交日顺延） |
