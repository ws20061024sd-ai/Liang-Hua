## 一、行业共识：回测最大的敌人

回测中所有系统性错误有一个共同特征：**它们只让回测看起来更好，永远不会让它看起来更差**。这是一个不对称的风险——你永远不会因为一个Bug而低估收益，只会高估。

```
回测欺诈金字塔（从底层到顶层）：
  
  基础层：数据源不同（AKShare vs JoinQuant vs Wind）
     ↓ +1-3pp
  交易成本层：忽略滑点/冲击成本/最低佣金
     ↓ +2-5pp  
  数据时效层：财报未滞后、用后复权价格
     ↓ +3-8pp
  幸存者偏差层：回测池不含退市/ST股
     ↓ +5-30pp
  过拟合层：参数对着全量数据调到最优
     ↓ +10-50pp
```

**每往上一层，虚高幅度翻倍。**

## 二、国际上公认的10大回测错误及对策

> 来源：HedgeFundAlpha (2025), QuantConnect, Vontobel (2026), S&P Global PIT 研究

### 错误 1：前视偏差（Look-Ahead Bias） 🔴

**定义**：在历史时间点 T 做出了需要 T+1 或之后信息才能做出的决策。

**典型场景**：
| 场景 | 具体表现 | 虚高幅度 |
|------|------|:--:|
| 财报未滞后 | Q1 财报截止 3/31，回测 4/1 就用到了 Q1 ROE（实际要到 4 月底才披露） | +3-8pp |
| 后复权价格 | 用后复权价格计算动量因子（隐含了未来的分红送股信息） | +1-3pp |
| 同日信号+执行 | 用当日收盘价产生信号，同时以收盘价成交（实盘不可能） | +2-5pp |
| 指数成分股回溯 | 用今天的沪深300成分股名单跑 2019 年回测 | +1.5-2pp |
| 财报重述覆盖 | 数据库只保留最新重述值，覆盖了当时实际披露的值 | 不定 |

**行业标准解法**：
```
Point-in-Time (PIT) 数据：
  - 每条数据标注两个时间戳：值日期(什么时候的) + 披露日期(什么时候公开的)
  - 回测在时间点 T 只能看到 '披露日期 <= T' 的数据
  
没有 PIT 数据库时的替代方案（本项目采用）：
  - 财报数据统一滞后 120 天（覆盖年报 4 个月披露延迟）
  - 行情数据用前复权（不用后复权）
  - 信号用 T 日收盘价产生 → T+1 日开盘价执行
```

**LLM 前视偏差（2026 年新发现）**：
ArXiv 论文 (2605.24564) 发现 LLM 在训练时已经"记住了"历史股价走势。当你用 LLM 辅助策略开发时，模型可能无意识地给出基于未来知识（而非当时可得信息）的建议。论文提出的 FinCAD 方法能将样本内回测收益削减 **67.1%**。

### 错误 2：幸存者偏差（Survivorship Bias） 🔴

**定义**：回测股票池只包含"现在还活着"的公司，那些已退市/ST/被并购的公司自动消失。

**严重程度（A股）**：
- 美股 1926-2016 年 **78%** 上市公司已退市
- A 股近年强制退市数量持续上升
- 若只用现存股票回测，收益虚高可达 **30-300%**
- 回测永远"碰不到"退市雷——回测赚钱的股票恰恰是因为它们活下来了

**更隐蔽的变种——代码变更污染**：
一家公司被借壳上市，新注入的财报数据可能被数据库"追溯平铺"到借壳前的历史截面上。回测在 2018 年"看到"了 2021 年才重组成功的新业务财报 → 虚假交易信号。

**行业标准解法**：
```
全历史动态股票池：每个历史时点上，股票池 = 当日真实挂牌名单
  - 退市股票不删除，保留退市前全部历史数据
  - 退市日之后标记为"不可交易"
  - 代码变更/借壳/重组做时序隔离
```

### 错误 3：交易成本低估 🟡

**A股完整交易成本**：

| 成本项 | 费率 | 收取方 | 说明 |
|------|:--:|------|------|
| 佣金 | 万1~万2.5 | 券商 | 双边，最低5元/笔 |
| 印花税 | 千1 (0.1%) | 国家 | **仅卖出**，政策刚性 |
| 过户费 | 万0.1 | 中登 | 双边 |
| 滑点 | 0.1%~0.5% | 市场 | 大盘蓝筹低，小盘股高 |
| 冲击成本 | 0.05%~0.3% | 市场 | 随交易量非线性增长 |

**关键认知——最低5元佣金是小资金杀手**：
```
如果每次交易 1,000 元：
  佣金 = max(5, 1000×0.00025) = 5元 = 0.5% ← 而非万2.5！

每次交易 5,000 元：
  佣金 = max(5, 5000×0.00025) = 5元 = 0.1% ← 仍比机构成本高 4 倍

往返一次最低成本：
  买入佣金 5 + 卖出佣金 5 + 印花税(5000×0.001=5) = 15元
  占 10,000 本金 = 0.15% 仅佣金，加滑点后约 0.3-0.5%
```

**行业建议**：
- 回测成本参数按 **2倍实盘成本** 做压力测试
- 年化换手率控制在 100-300%（超过则成本侵蚀严重）
- 单笔交易金额尽量 > 2万元（让佣金率接近万2.5而非最低5元）

### 错误 4：过度拟合（Overfitting） 🟡

**"100 个策略里总有一个看起来很好——但那只是运气"**

Harvey, Liu & Zhu 的经典研究：在测试了 100+ 个策略变体后，需要 **t-statistic > 3.0** 而非传统的 2.0 才算显著。

**行业标准防御**：

```
Walk-Forward 验证：
  训练集(2019-2022) → 验证集(2023-2024) → 测试集(2025-2026，只用一次)
  
参数稳健性检查（Island Volume Selection）：
  ❌ 不选"峰值参数"（某个参数值回测最好，相邻参数差很多）
  ✅ 选"平台参数"（一个区间内回测都稳定）
  
Deflated Sharpe Ratio：
  考虑"你试了多少个策略"后的真实显著性
```

### 错误 5：市场制度变化 🟡

2015 年有效的小市值策略到 2024 年可能因为注册制改革和量化拥挤而失效。回测跨越的制度变化节点：

| 年份 | 事件 | 对策略的影响 |
|------|------|------|
| 2016 | 熔断机制 | 1月暴跌，波动率结构变化 |
| 2019 | 科创板开板 | 涨跌停 20%，新市值结构 |
| 2020 | 新证券法 | 退市制度加强 |
| 2021 | 量化私募爆发 | 因子拥挤度飙升 |
| 2023 | 全面注册制 | 壳价值归零，小市值因子失效 |
| 2024 | 退市新规 | 微盘股流动性危机 |

## 三、开源项目架构参考

### 3.1 数据管道设计模式

经过对 GitHub 上 15+ 个量化开源项目的调研，成熟的数据管道普遍采用分层架构：

```
Layer 0: 数据采集 (Ingestion)
  ├── AKShare / Baostock / Tushare / 东方财富 → 原始数据
  ├── 多源智能路由（源A失败 → 自动切换源B）
  └── 限速/重试/断点续传

Layer 1: 数据标准化 (Canonical)
  ├── 统一格式：code(6位) + date(YYYY-MM-DD) + 字段
  ├── 列式存储：Parquet/Feather（比CSV快5-10倍）
  └── DuckDB/SQLite 作为查询层

Layer 2: 特征工程 (Features)
  ├── 因子计算（从标准化数据派生）
  ├── PIT 时间戳校验（财报披露日期 ≤ 回测当前日期）
  └── 去极值/中性化/标准化

Layer 3: 数据集市 (Mart)
  ├── 策略专用视图（宽表）
  └── 回测/实盘共享同一数据源
```

### 3.2 本项目当前架构对标

| 层级 | 行业标准 | 本项目现状 | 差距 |
|------|------|------|:--:|
| 数据采集 | 多源路由 + 断点续传 | AKShare+BaoStock，有重试 | 无断点续传 |
| 数据标准化 | Parquet + DuckDB | SQLite + pandas | SQLite对时序查询足够 |
| PIT 时间戳 | 值日期+披露日期双时间戳 | ROE 刚加了 120 天滞后 | PE/PB 需要确认是否有 PIT 问题 |
| 特征工程 | 统一因子库 | engine/factors.py 已统一 ✅ | — |
| 回测/实盘一致性 | 共享因子库+数据源 | 已统一 ✅ | 聚宽策略仍需手动同步 |
| 参数管理 | Config-driven | settings.py 集中管理 ✅ | — |
| 测试 | 单元测试+回归测试 | 26 个测试 ✅ | 缺少回测结果回归测试 |

## 四、A股量化数据源的已知问题及规避

### 4.1 各数据源比较

| 维度 | AKShare | Baostock | Tushare | JoinQuant(云端) | 东方财富 |
|------|:--:|:--:|:--:|:--:|:--:|
| 日线数据 | ✅ 稳定 | ✅ 稳定 | ✅ 需token | ✅ 云端免维护 | ✅ 可用 |
| PE/PB | ❌ 不直接提供 | ✅ 日频历史PE/PB | ✅ 需积分 | ✅ | ✅ |
| ROE | ✅ 同花顺接口 | ❌ 不提供 | ✅ fina_indicator | ✅ indicator.roe | ✅ |
| 成本 | 免费 | 免费 | 免费(低积分) | 免费 | 免费 |
| PIT 支持 | ❌ 无 | ❌ 无 | ❌ 无 | ⚠️ 部分支持 | ❌ 无 |
| 前复权/后复权 | qfq/hfq 可选 | qfq/hfq 可选 | qfq/hfq 可选 | fq='pre'/'post' | qfq/hfq |

**关键结论**：国内免费数据源**没有一个**提供真正的 Point-in-Time 数据。因此**必须自己实现滞后逻辑**。

### 4.2 本项目已知的数据风险矩阵

| 风险 | 严重度 | 状态 | 规避措施 |
|------|:--:|:--:|------|
| ROE 未滞后（已修复） | 🔴 | ✅ 120天滞后 | §二 错误1 |
| PE/PB 日频数据是否 PIT？ | 🟡 | ⚠️ 待确认 | Baostock 日频 PE/PB 是当日行情衍生，应为 PIT |
| 后复权价格使用 | 🟡 | ✅ 已用前复权 | `qfq` 参数 |
| 退市股票缺失 | 🟡 | ⚠️ 未处理 | 沪深300 成分股退市率低，短期影响小 |
| 财务数据版本覆盖 | 🟢 | ⚠️ 未处理 | 同花顺 ROE 是否会被重述覆盖待确认 |
| 不同数据源价格差异 | 🟡 | ⚠️ 无法消除 | AKShare vs JoinQuant 数据商不同 |

### 4.3 财报披露时间线（A股规则）

```
Q1 财报 (3/31截止) → 披露截止日: 4/30 → 实际可用: 5月初   滞后 ~30天
Q2 半年报(6/30截止) → 披露截止日: 8/31 → 实际可用: 9月初   滞后 ~60天  
Q3 财报 (9/30截止) → 披露截止日: 10/31 → 实际可用: 11月初  滞后 ~30天
Q4 年报 (12/31截止) → 披露截止日: 4/30 → 实际可用: 5月初   滞后 ~120天

统一滞后 120 天(4个月)是最保守安全的做法。
```

## 五、本地回测与云端回测的角色定义

### 5.1 为什么不能只靠一个

这个问题是整个量化行业的结构性难题：

```
          本地回测                      云端回测（聚宽）
          ────────                      ────────────
优点：     秒级迭代                    完整数据+风控+执行模拟
          随时改参数                   机构级数据质量
          完全可控                     内置PIT保护

缺点：     数据源有限                   依赖第三方
          成本/风控模拟不足             无法自动化
          无PIT保护(需自己实现)          改参数要手动粘贴代码
```

### 5.2 行业通行做法：双引擎验证

```
开发阶段 → 本地回测（快速迭代，方向验证）
         → 样本外验证
         → 云端回测（真理确认）
         → 小资金实盘（成本校准）
         → 正式上线

决策规则：
  - 本地回测通过 + 云端回测失败 → 相信云端，放弃策略
  - 本地回测失败 + 云端回测通过 → 排查本地数据/代码 Bug
  - 两者都通过 → 进入小资金实盘验证
  - 两者都失败 → 放弃
```

### 5.3 本项目的对标方法

```
Level 1 (快速): TOP_N = [5,10,15,20,30] 排序一致性
  → 本地和云端收益/夏普的最高点是否在同一个TOP_N
  
Level 2 (中): 逐月持仓重合度
  → 取3个代表性月份，对比前20持仓重合度 ≥ 60%
  
Level 3 (深): 逐因子排查
  → 每个因子的分布统计(m/p5/p95/std)差异 ≤ 30%
```

## 六、小资金量化交易的特殊考虑

### 6.1 成本结构完全不同

| 维度 | 机构（1亿+） | 个人小资金（1-10万） |
|------|:--:|:--:|
| 佣金率 | 万1以下 | 万2.5，且最低5元 |
| 滑点 | 可用算法交易降低 | 市价单，全额承受 |
| 冲击成本 | 可拆单 | 无此选项 |
| 策略容量 | 是硬约束 | 不是问题 |
| 分散化 | 可持50+只 | 资金限制2-5只 |

### 6.2 策略设计建议

```
✅ 月频调仓（12次/年 × 2边 = 24笔交易，成本可控）
✅ 沪深300成分股（流动性好，滑点低）
✅ 前复权价格（避免后复权引入的未来信息）
✅ 等权持仓（简化操作，减少交易次数）
❌ 日频/周频调仓（成本吞噬收益）
❌ 小盘股/微盘股（滑点不可控）
❌ 超过5个因子的复杂模型（样本外更可能失效）
```
