### 2026-06-17 数据全面审查结果

对 `data/stocks.db` 进行全面审查，发现三个问题：

```
数据库全景：
  daily_kline      485,694 行  ✅ 300只，2019-2026，pct_change 无NULL
  stock_info            300 行  ✅
  financial_data        572 行  🔴 仅2只股票（001391, 600930）——缺失 298/300
  signal_history        188 行  🟡 4天数据，BUY 21/SELL 167
  sector_history         90 行  🔴 仅1天（2026-06-09）
```

#### 问题一：财务数据缺失 99.3% — 根因是多线程登录Bug

**根因**：`financial_downloader.py` 使用 8 线程并行下载 Baostock 数据，但 `bs.login()` 只在主线程调用。Baostock 的登录状态**不跨线程共享**，子线程中所有 `bs.query_history_k_data_plus()` 调用都报 "you don't login"，静默返回 None。仅 2 只股票因竞态条件侥幸成功。

**影响**：多因子引擎的价值因子（PE/PB, 权重20%）和质量因子（ROE, 权重15%）完全失效，因子得分仅靠4个纯价格因子（65%权重）计算。

**修复方案**：每个子线程独立调用 `bs.login()` / `bs.logout()`，或改为顺序下载（300只×0.3s≈90秒，对月频数据完全可接受）。详见 [项目梳理与优化方案](项目梳理与优化方案.md) Bug 4。

#### 问题二：板块数据仅1天

`sector_history` 只有 2026-06-09 的数据。`report.py` 在此之后再未成功运行过。板块趋势分析、行业轮动等依赖5日动量的功能全部瘫痪。

**修复**：确认服务器 cron 中 `report.py` 正常运行；或在 `run.py` 中每次也调用 `save_today_sectors()` 积累数据。

#### 问题三：信号严重偏空（167卖出 vs 21买入）

市场可能确实偏弱，但 88.8% 卖出比例值得持续观察。与大盘择时状态对照确认。

