## 〇、回测一致性问题 —— 当前最高优先级 🔴

### 问题定性

本地回测（`backtest/local_factor_backtest.py`）与聚宽回测（`docs/策略/聚宽回测_多因子选股.py`）的结果不一致，且偏差幅度大（本地 TOP_N=3 显示 35% 年化，聚宽仅 0.02%）。

经逐行对比，**本地回测有两项结构性错误 + 一项数据缺失 + 三项配置/逻辑差异**，不是"精度问题"，是"代码和数据就有问题"。聚宽结果为真，本地结果不可信。

### 五项差异详解

#### 🔴 差异一：动量因子公式错误（结构性 Bug）

**位置**：`engine/factors.py:15-29`（`momentum()`）+ `engine/factors.py:65-72`（`momentum_vectorized()`）

**本地当前（错误）**：
```python
total_ret  = (close[-1] - close[-252]) / close[-252]   # 12个月总收益
recent_ret = (close[-1] - close[-21])  / close[-21]     # 最近1个月收益
momentum   = total_ret - recent_ret                      # 两者相减
```

**聚宽（正确）**：
```python
momentum = (close[-21] - close[-252]) / close[-252]      # 12-1动量（标准学术定义）
```

**数学差异**：本地结果 = 聚宽结果 × (1 + 最近1月收益率)。只有最近一个月不涨不跌时两者才碰巧相等。

**实例**：假设股价 12 月前 100、1 月前 120、现在 130：
- 聚宽：(120 - 100) / 100 = **20.0%** ✓
- 本地：(130-100)/100 - (130-120)/120 = 30% - 8.33% = **21.67%** ✗（偏高1.67pp）

**影响**：所有动量得分都偏移了 (1+近月收益) 的倍数。最近涨得多的股票动量被高估，跌得多的被低估。月频调仓下这个偏差会被放大。

**修复**：`engine/factors.py` 两处 momentum 函数各改一行，10 分钟。

---

#### 🔴 差异二：ROE 数据缺失（数据源硬伤）

**位置**：`data_fetcher/financial_downloader.py` → `financial_data` 表

**现状**：Baostock 估值接口（`query_history_kline_plus`）只提供 PE/PB/PS/PCF，**不提供 ROE**。本地 `financial_data` 表根本没有 `roe` 列的有效数据，所有股票的 ROE 因子得分 = 0。

**影响**：ROE 占权重 15%。缺失意味着：
- 高质量股票（高 ROE）和低质量股票得分无区分
- 002 策略 45% 进攻 + 30% 防御 + **15% 质量** → 质量端完全失效
- 本地选股等价于只有 85% 权重在工作

**解决方案（见下方 §方案设计）**：
- 方案A（推荐）：AKShare `stock_financial_analysis_indicator()` 拉取 ROE，存入 `financial_data`
- 方案B（备选）：Tushare `fina_indicator` API — 有 token 但需要额外代码
- 方案C（妥协）：本地回测去掉 ROE 因子，权重重新分配给价格因子 → 但这改变了策略定义，对标意义更差

---

#### 🟡 差异三：因子引擎权重 ≠ 聚宽策略权重

| 因子 | factor_engine.py（v1） | 聚宽策略（v2.1） | local_factor_backtest.py |
|------|:--:|:--:|:--:|
| momentum | 25% | **30%** | 30% ✅ |
| volatility | 15% | **20%** | 20% ✅ |
| reversal | 15% | 15% | 15% ✅ |
| turnover | 10% | 10% | 10% ✅ |
| pe | 10% | 10% | 10% ✅ |
| pb | 10% | **0%** | 0% ✅ |
| roe | 15% | 15% | 15% ✅ |

**问题**：`factor_engine.py` 仍使用 v1 权重（25/15/15/10/20PB含10/15），而聚宽策略 v2.1 是 30/20/15/10/10/0/15。PB 因子在单因子回测中确认是负收益因子已被砍掉。

**影响**：实盘信号（run.py → factor_engine）和回测用的权重不一样。实盘基于次优权重选股。

**修复**：`factor_engine.py` 权重改为 v2.1，5 分钟。

---

#### 🟡 差异四：换手率因子数据源不同

| 位置 | 数据 | 含义 |
|------|------|------|
| 聚宽策略 | `volume` 列 → v20/v60 比 | 成交量比（20日均量/60日均量） |
| local_factor_backtest | `volume` 列 → v20/v60 比 | 同上 ✅ |
| factor_engine.py | `turnover` 列（DB 中的换手率%） | 真实换手率 |

**问题**：聚宽策略根本没用"换手率"——它用的是**成交量比率**（Volume Ratio），这是个流动性变化指标。但 `factor_engine.py` 用 DB 里的真实换手率数据（%），含义不同。

**影响**：两个因子的数值范围和分布不同。Z-score 标准化后，排序会有变化。中等影响。

**修复**：统一为成交量比率（与聚宽一致），10 分钟。

---

#### 🟡 差异五：无涨停/停牌过滤

聚宽 `select_top_stocks()` 在选股后会跳过涨停和停牌股票，但本地回测没有这个步骤。

**影响**：某些月份本地可能选到当时涨停的股票，计入"买入"但实际无法成交。这会**虚高本地回测收益**。

**修复**：利用已有的 `daily_kline.pct_change` 列（涨跌幅 9.9%+ = 涨停），在选股时过滤，15 分钟。

如果差距仍然很大，说明还有其他未发现的差异——需要进一步排查。

## 方案设计

### 整体思路

```
聚宽回测 = 真理（完整数据 + 正确公式 + 风控过滤）
本地回测 = 快速迭代工具（方向验证 + 参数探索）
```

目标不是让本地 100% 等于聚宽（不同数据源不可能完全一样），而是：
1. **公式对齐**：同样的因子计算逻辑，同样的权重
2. **数据补齐**：ROE 必须有真实数据
3. **逻辑补齐**：涨停/停牌过滤
4. **方向可信**：本地改参数后的涨跌方向与聚宽一致

### ROE 数据获取方案

#### 方案A：AKShare `stock_financial_analysis_indicator()` ← 推荐

```python
import akshare as ak

# 单只股票的财务分析指标
df = ak.stock_financial_analysis_indicator(symbol="000001")
# 返回包含 ROE、ROA、毛利率、净利率等数十个指标

# 覆盖：沪深300全部 + 历史季度数据
# 成本：¥0（AKShare 免费）
# 风险：接口稳定性未知，需实测
```

**优点**：免费、与现有 AKShare 体系一致、数据覆盖面广
**缺点**：接口可能限频，大量下载需要控制速率

#### 方案B：Tushare `fina_indicator` API ← 备选

```python
import tushare as ts
pro = ts.pro_api(token=TUSHARE_TOKEN)
df = pro.fina_indicator(ts_code='000001.SZ', start_date='20190101')
# 返回 ROE、ROA、EPS 等
```

**优点**：接口稳定、数据质量高
**缺点**：需要 token（已有）、有积分限制（免费版可能有限额）

#### 方案C：从 Baostock 利润表 + 资产负债表计算 ← 兜底

通过 Baostock `query_profit_data()` 获取净利润，`query_balance_data()` 获取股东权益，自行计算 ROE = 净利润 / 股东权益。

**优点**：与现有 Baostock PE/PB 同一数据源，一致性好
**缺点**：计算复杂、需要两次查询、可能有时滞

### 推荐路径

```
第一步：实测 AKShare 方案（10分钟验证一只股票）
  → 成功：批量下载 300 只 ROE → 存入 financial_data 表
  → 失败：转 Tushare 方案

第二步（如果 AKShare 和 Tushare 都不可行）：
  → 用 Baostock 计算 ROE
```
