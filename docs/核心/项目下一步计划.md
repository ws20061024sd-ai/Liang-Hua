## 二、Phase 1：代码改动（详细步骤）

### 1.1 run.py 接入数据校验

**当前**：run.py 直接开始下载，不检查数据健康状态。

**改为**：下载完成后、生成信号前，跑数据校验。阻断则不推送信号，改推告警。

```python
# run.py 新增（下载完成后、策略运行前）
import subprocess, sys
result = subprocess.run(
    [sys.executable, 'scripts/data_check.py', '--block'],
    capture_output=True, text=True
)
if result.returncode != 0:
    # 数据异常 → 推送告警，不推信号
    send_alert("数据校验未通过", result.stdout)
    sys.exit(1)
```

**改动文件**：`run.py`

### 1.2 策略版本号更新

三个策略文件头部的 `version` 从 `"1.0"` 改为 `"2.0"`，记录参数变更：

| 策略 | 旧参数 | 新参数 |

**改动文件**：`strategies/ma_cross.py`, `strategies/momentum_breakout.py`, `strategies/mean_reversion.py`

### 1.3 回测文件路径修复

`backtest/three_strategy_backtest.py` 和 `backtest/local_factor_backtest.py` 的 `PYTHONPATH` 问题——直接 `python backtest/xxx.py` 会报 `ModuleNotFoundError: No module named 'config'`。

## 五、Phase 4：止损接入（后续迭代）

### 5.1 为什么现在不做

止损需要跨天追踪持仓价格。当前系统每天独立生成信号，不维护持仓状态。接入止损需要：
- 持仓追踪模块（记录买入价+最高价）
- 每日检查止损触发
- 生成 STOP_LOSS 类型信号

这是 ~2 小时的工程量，作为 Phase 4 独立迭代。

### 5.2 设计方案（预留）

```
engine/position_tracker.py（新建）
  - load_positions(): 从 signal_history 读取当前持仓
  - check_stops(): 检查每只持仓是否触发移动止损
  - 触发条件: current_price < peak_since_entry * (1 - TRAILING_STOP)
  - 返回 STOP_LOSS 信号列表

engine/runner.py 改动:
  - run_strategies() 返回信号前, 调用 check_stops()
  - STOP_LOSS 信号优先于所有其他信号

run.py 改动:
  - 每日信号推送包含止损信号
```
