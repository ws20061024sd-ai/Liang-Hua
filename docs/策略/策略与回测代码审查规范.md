## 1. 审查总则

### 1.1 核心原则

```
每一行策略代码在被回测验证之前，都必须先通过本审查清单。

审查不是可选的——策略代码的错误会导致三种毁灭性后果：
  1. 回测结果虚假（看起来赚钱，实盘亏钱）
  2. 回测静默失败（收益0%，策略根本没在运行）
  3. 回测崩溃报错（浪费时间排查）
```

### 1.0 研究先行原则 🆕

> 2026-06-18 新增——聚宽代码改了8次的血泪教训。

**在写任何跨平台/新环境代码之前，必须先完成以下三件事：**

```
□ 1. 搜索文献
   - 搜索目标平台的官方文档 + 社区最佳实践
   - 用 /deep-research 或 WebSearch 系统调研
   - 搞清楚 "API 到底返回什么" 而非 "我以为它返回什么"

□ 2. 环境验证
   - 在目标平台上跑 5 行代码确认数据格式（§5 第1步）
   - 打印 type() / columns / shape → 和文档对比
   - 文档和实测不一致 → 以实测为准！

□ 3. 制定方案
   - 基于验证结果写数据流（不是基于猜测）
   - 画清楚: API 返回 → 中间格式 → 最终格式
   - 确认每一步的类型转换

违反本原则的后果：
  聚宽多因子策略 → 基于错误的宽表假设 → 8次报错 → 2天浪费
  根因：没先跑 5 行代码确认 get_price(panel=False) 的实际格式
```
```

### 1.2 审查时机

| 时机 | 审查深度 |
|------|---------|
| 新策略写完 | 完整审查（全部25项） |
| 修改因子/参数 | 审查§2（策略设计）+ §5（最小验证） |
| 跨平台移植（本地→聚宽） | 审查§3 + §4（代码+API） |
| 回测结果可疑（收益0%或异常高） | 审查§5（最小验证）+ §6（速查表） |

### 1.3 审查流程

```
策略代码写完
    ↓
① 自审：对着本清单逐项过
    ↓
② 最小验证：在目标平台跑5行代码确认环境正常（§5）
    ↓
③ 样本外检查：选1个月数据手工验算（§2.7）
    ↓
④ 正式回测
    ↓
⑤ 结果检查：收益0%？异常高？→ 回到①
```

## 2. 策略设计审查

### 2.1 未来函数检查 🔴

> **最高优先级。** 未来函数让回测看起来完美，实盘一文不值。

**检查项**：

```
□ 所有数据是否在信号生成时间点之前可得？
   - 收盘价：当日收盘后可用（日线策略用收盘价OK，盘中策略必须用前一周期）
   - 财务数据：季报发布日之后才可用（不能用12月的PE选1月的股）
   - 技术指标：shift(1)确保没有用到当日数据做决策

□ 回测中是否有任何 "今天的数据" 被用于 "今天的决策"？
   例：用当日收盘价判断是否买入，然后用当日收盘价成交 → 未来函数
   正确：用昨日收盘价判断，用今日开盘价/收盘价成交

□ 数据标准化/排名是否在每个时间点独立完成？
   例：用全样本的均值标准差做 z-score → 未来函数
   正确：每个调仓日只用截至该日的数据做标准化

□ get_price 是否传了正确的 end_date？
   例：end_date=今日 → 能看到今日数据 → 如果用今日数据决策 → 未来函数
   正确：end_date=前一日（context.previous_date）
```

**我们的代码自查**：

```python
# ✅ 正确：动量因子只用到前一日
momentum = (close_df.iloc[-21] - close_df.iloc[-252]) / close_df.iloc[-252]

# ❌ 错误：用全样本做 z-score（偷看未来）
all_data = get_price(start='2019-01-01', end='2026-06-01')  # 包含未来数据
df['score_z'] = (df['score'] - df['score'].mean()) / df['score'].std()  # 用了未来均值和标准差

# ✅ 正确：每个时间点独立标准化
# 每月调仓时，只有截至当月的 close_df，在该范围内做 z-score
```

### 2.2 幸存者偏差检查 🔴

```
□ 回测股票池是否每个时间点使用当时的成分股？
   - 聚宽：get_index_stocks() 返回当前成分股（幸存者偏差！）
   - 正确做法：每个调仓日用当时的指数成分股（聚宽研究环境支持）
   - 接受程度：对于沪深300月频策略，偏差约2-5%/年

□ 是否排除了已退市股票？
   - 聚宽默认包含退市股票数据（退市后价格为NaN） → 已自动处理
   - 本地SQLite：如果只下载当前成分股 → 存在偏差
```

### 2.3 因子逻辑检查 🟡

```
□ 每个因子的方向是否正确？
   例：动量（正向）、低波动（负向——标准化后取负）、PE（负向——取负）

□ 因子计算是否有足够的样本量？
   - 动量：需要 ≥252 个交易日（1年）
   - 波动率：需要 ≥60 个交易日
   - 反转：需要 ≥6 个交易日
   - 因子不足3个的股票是否被排除？（min_factors 检查）

□ 因子值域是否合理？
   - 动量：通常 -0.5 ~ +2.0；超过 +10 = 异常（新股/复牌暴涨）
   - PE：通常 5 ~ 200；<0（亏损）和 >500（微利）应排除
   - 波动率：年化 0.15 ~ 0.80 正常；>1.5 可疑

□ PE/PB/ROE 缺失时，权重是否正确重新分配？
   - 缺失因子应设为 0，有效因子自动承担其权重
   - 检查：缺失后 实际权重之和 ≠ 1.0 → 得分整体偏低 → 错误
```

---

### 2.4 交易规则检查 🟡

```
□ T+1 是否正确模拟？
   今日买入 → 明日才能卖出（聚宽默认 T+1，无需额外处理）

□ 涨跌停是否处理？
   - 涨停价买入 → 不可能成交 → 应排除
   - 跌停价卖出 → 不可能成交 → 应保留（等待后续交易日）
   - 检查 is_limit_up() 逻辑

□ 停牌是否处理？
   - 停牌日 prices 为 NaN → close_series.dropna() 自动跳过 ✅
   - 调仓日 停牌股 → 跳过（get_current_data()[stock].paused 或 last_price=None）

□ 手续费/滑点是否设置？
   - 佣金：双向 0.025%-0.03%（聚宽 OrderCost）
   - 印花税：卖出 0.05%
   - 滑点：0.1%（FixedSlippage）
   - min_commission：5元/笔

□ 仓位计算是否考虑整数手？
   - A股最小 100 股 → order_target_value 自动取整 ✅
```

---

### 2.5 调仓逻辑检查 🟡

```
□ 调仓频率是否合理？
   - 日频：交易成本高（200+次/年），需要较高 Alpha 才能覆盖
   - 月频：成本可控（12次/年），适合多因子

□ 调仓日是否有流动性？
   - 月初/月末流动性通常正常
   - 节假日前一个交易日可能缩量

□ 调仓时是否先卖后买？
   - 先卖 → 释放现金 → 再买 ✅
   - 先买 → 现金不足 → 部分成交 → 持仓偏离

□ 最大持仓数是否与资金匹配？
   - 1万：2只；5万：5只；10万：10-15只
   - 持仓过多 → 单票金额太小 → 手续费占比过高
```

### 2.6 参数敏感性检查 🟢

```
□ 是否测试了至少2组参数？
   - 权重 ±5%：动量 20%/25%/30%
   - TOP_N ±5：10/15/20
   - 回测区间：至少覆盖完整牛熊（≥5年）

□ 参数变更是否导致结果剧烈变化？
   如果 25%→30% 导致年化从 +10% 变 -5% → 过拟合
   如果 TOP_N 10→20 导致年化从 +15% 变 +2% → 策略不稳定

□ 是否记录了参数选择理由？
   - "动量 25% 是业界常见权重" ✅
   - "试了 50 组参数选了最好的" ❌（过拟合）
```

### 2.7 手工验算 🟡

> 选一个月（如 2020-01-02），手工计算 Top 3 股票，和回测日志对比。

```
验证步骤：
  1. 选一个调仓日：2020-01-02
  2. 从缓存/数据库取截至当日的 close 数据
  3. 手算 1 只股票的 动量/波动率/PE
  4. 和回测日志中该日该股票的得分对比
  5. 确认得分一致 → 因子逻辑正确
  6. 确认 Top 3 和回测买入名单一致 → 选股逻辑正确
```

## 3. 回测代码审查

### 3.1 数据加载 🟡

```
□ 数据是否在 initialize() 中预加载？
   - 高频调用（如月频×90次）→ 必须缓存到 g 对象
   - 低频调用（如仅 initialize 时用一次）→ 可以直接查

□ get_price 是否重复调用？
   搜索代码中所有 get_price / attribute_history：
   - 出现在循环内 → 🔴 严重性能问题
   - 出现在 run_daily/run_monthly 回调内，且缓存可用 → 🟡 建议优化

□ 数据切片是否正确？
   - .loc[:date] → 包含 date 当天及之前 ✅
   - .iloc[-260:] → 最近260行 ✅
   - tail(260) → 最近260行 ✅
```

### 3.2 批量计算 vs 逐股循环 🟡

```
□ 因子计算是否使用了 pandas 向量化操作？
   检查代码中是否有 for stock in stocks: ...
   → 如果是对每只股票独立计算 → 🟡 可以优化（批量更快）
   → 如果是简单的列操作 → ✅ 已经向量化

   向量化 vs 循环对比：
   # ❌ 慢：300次循环
   for stock in stocks:
       close = df[stock]
       momentum = (close[-21] - close[-252]) / close[-252]

   # ✅ 快：一次批量
   momentum_series = (df.iloc[-21] - df.iloc[-252]) / df.iloc[-252]
```

### 3.3 数据维度检查 🔴

```python
□ 每次 DataFrame 操作后是否检查了 shape/type？
   - .iloc 切片后：df.shape 确认行数正确
   - .xs / ['col'] 取值后：type(df) 确认是 DataFrame 而非 Series
   - .loc 筛选后：len(df) > 0 确认非空

□ 是否有 _ensure_df() 防护？
   任何从 MultiIndex / xs / 单列索引取值的地方：
   if isinstance(result, pd.Series):
       result = result.to_frame()
```

### 3.4 错误处理 🟡

```
□ try/except 是否吞掉了关键错误？
   - 静默 except: pass → 🔴 禁止（Bug 永久隐藏）
   - except Exception: log.warn(...) → ✅ 至少记录日志
   - except SpecificError: handle → ✅ 精确处理

□ 空数据是否有兜底？
   - scores is None → return（不调仓）✅
   - len(scores) < 5 → return（不够分散）✅
   - 无买入信号 → 也要推送/记录（不能静默）✅
```

## 6. 常见错误速查表

### 6.1 错误信息 → 根因 → 修复

| 报错信息 | 根因 | 修复 |
|---------|------|------|
| `ParamsError: 取多只股票数据时不能跳过停牌` | `skip_paused=True` | 去掉 `skip_paused` |
| `'Series' object has no attribute 'columns'` | `get_price[...]` 返回了 Series | 用 `.xs()` + `_ensure_df()` |
| `NameError: name 'current_data' is not defined` | 聚宽 API 版本差异 | `get_current_data()` 函数调用 |
| `有效得分过少` | 因子计算失败或数据取不到 | 检查 §5.1 取数 + 增加日志 |
| 策略收益始终 0% | Panel 问题 / 数据全是 NaN | 加 `panel=False` |
| 每月 WARNING: 不建议继续使用 panel | 未设 `panel=False` | 加 `panel=False` |
| `DataFrame' object has no attribute 'append'` | Pandas 3.x 不兼容老库 | Monkey-patch `append` |
| `'NoneType' object has no attribute ...` | API 返回 None 未检查 | 加 `if x is not None` |
| `OperationalError: no such column` | 表结构不同步 | `ALTER TABLE ADD COLUMN` |
| Baostock: `you don't login` | 多线程登录状态不共享 | 单线程顺序下载 |
| `可用股票不足: 0` 持续所有月份 | get_price columns 格式与 get_index_stocks 不匹配 | 先跑环境验证确认列名格式 |
| `DataFrame has no attribute 'columns'` | 数据返回了 Series 而非宽表 | panel=False 返回长格式，需 .pivot() |
| 回测收益始终 0%、无交易 | get_price 数据在回测中为空（end_date 硬编码取不到） | 用 context.previous_date |
| get_price columns = ['time','code','close'] | 这是**正常的长格式**，不是错误！| .pivot(index='time', columns='code', values='close') |

### 6.2 症状 → 根因 → 修复

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| 回测收益 0%、无交易 | Panel问题/数据取不到/因子全NaN | 检查第1步取数 + 打印1个月得分 |
| 回测收益极高(>100%/年) | 未来函数/幸存者偏差/忘记手续费 | 审查§2.1+§2.2+§2.4 |
| 每月都买同一批股票 | 因子值不变(用的全样本标准化) | 检查 z-score 是否在每个时间点独立计算 |
| 调仓日无交易 | 停牌/涨停过滤太严/现金不足 | 打印选股前股票数和排除原因 |
| 回测越来越慢 | get_price 在循环内重复调用 | 搜索代码中所有 get_price 位置 |
