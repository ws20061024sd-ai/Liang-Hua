# 策略打磨与新增规范

> 2026-09-09 · 适用范围：修改现有策略参数/逻辑、新增策略、下线策略
> 上位规范：`docs/核心/数据与回测正确性保障规范.md`（数据与回测宪法）

## 为什么需要这份规范

信号验证系统（L1 固定窗口 + L2 等权账本）已上线，策略改动不再靠"感觉"——每个策略的真实命中率、账本收益都在仪表盘「信号效果」页持续累积。**打磨有了数据依据，也就必须有了流程约束**：否则很容易滑向"反复调参直到历史数字好看"的过拟合陷阱。

同时，2026-09-09 发生过一次事故：策略页文案里的裸 `<` 字符破坏 HTML 结构，卡片 div 贯穿整页。**文案与代码的同步**也需要制度化。

## 核心原则

1. **机制理由优先，禁止纯调参**——改动的依据是"为什么这样改更合理"（如"震荡市假突破多，加过滤"），不是"这样调历史收益最高"。纯调参 = 拟合历史噪声，样本外必然失效。
2. **小步可回滚**——一次只改一个维度（参数 or 逻辑），能单独回退。
3. **参数进 settings**——策略文件禁止硬编码（宪法级要求）。
4. **验证闭环**——本地回测（方向）→ pytest（不破坏）→ 回放对比（信号质量）→ 聚宽（上线决策）。
5. **文案与代码同步**——改逻辑必须同步改策略页文案，并加测试防漂移。

## 一、策略打磨流程（修改现有策略）

### 第 0 步：数据诊断（改之前，必做）

看仪表盘「信号效果」页，定位问题类型：

| 症状 | 可能原因 | 改动方向 |
|---|---|---|
| L1 胜率 <50%（BUY 跑输大盘） | 信号方向不对/假信号多 | 加过滤条件（如趋势/量能） |
| L1 胜率高但 L2 亏 | 卖点问题（拿不住或卖太晚） | 调卖出规则 |
| 止损触发率高 | 入场时机差（买在短期高点） | 加回踩确认 |
| 某市场状态下特别差 | 策略与市场不匹配 | 调 regime 权重或加状态过滤 |

**写清楚"要解决什么问题"**（一句话，进 commit message）。没有数据支撑的改动不做。

### 第 1 步：改（一次一个维度）

- 参数调整 → `config/settings.py`
- 逻辑调整 → `strategies/xxx.py`（若涉及因子：`engine/factors.py` ↔ `backtest/local_factor_backtest.py` ↔ 聚宽策略三处同步）
- ❌ 禁止：同时改多个参数 + 改逻辑

### 第 2 步：本地验证（10 分钟内）

```bash
python -m pytest tests/ -q                              # 全绿
PYTHONPATH=. python backtest/local_factor_backtest.py   # 方向验证（5 个 TOP_N）
```

### 第 3 步：回放对比（15 分钟，打磨的核心环节）

```bash
# 先记录当前效果页数据（截图或记下 L1 胜率/超额、L2 收益）
# 重跑回放——新参数在历史数据上的表现（覆盖 replay 数据）
python scripts/signal_outcome.py --replay
```

**判定标准**：

| 结果 | 决策 |
|---|---|
| L1 胜率提升 ≥5pp 且样本 ≥50 条 | 值得继续 |
| L1 无改善 / 样本 <50 / 收益靠单笔异常 | 回滚 |

**防过拟合提醒**：回放是"同一条历史反复试参数"，调多了必然好看。只调 1-2 次，且必须有机制理由；重大改动必须过第 4 步。

### 第 4 步：聚宽确认（重大改动必做）

变化 >5pp 或改逻辑 → 按 `docs/策略/聚宽策略编码须知.md` 在聚宽验证。**聚宽 = 上线决策依据，本地 = 方向参考**（宪法级）。

### 第 5 步：上线与跟踪

```bash
git push && # 服务器
cd /root/Liang-Hua && git pull
```

- 上线后 2 周观察效果页 `real` 数据（真实钉钉信号的表现）
- 记录到 `docs/策略/策略回测报告.md`：改了什么、为什么、回放效果、实盘效果

## 二、新增策略流程

### 1. 设计（先想清楚再写代码）

- 什么时候买、什么时候卖、适合什么市场
- **机制理由**（不是"回测好看"）
- 与现有三策略的关系（互补还是重叠）

### 2. 实现

```python
# strategies/new_strat.py
class NewStrategy(BaseStrategy):
    name = "策略名"
    version = "1.0"
    style = "trend"        # trend | reversion —— 决定大盘择时的降权方向
    def calculate(self, df): ...
    def get_signal(self, stock_code, stock_name, df): ...
```

### 3. 注册（四处，缺一不可）

| 位置 | 内容 |
|---|---|
| `engine/runner.py` | STRATEGY_REGISTRY 加类 |
| `config/settings.py` | ENABLED_STRATEGIES 加类名 |
| `web/generate.py` STRATS | 策略页文案（含 **buy/sell 条件**，必须转义） |
| `docs/策略/策略回测报告.md` | 回测结果章节 |

### 4. 验证门槛（缺一不可）

| 环节 | 标准 |
|---|---|
| 单元测试 | ≥3 个：信号触发 / 边界（数据不足）/ 不触发 |
| 本地回测 | 5 个 TOP_N 跑赢基准 |
| pytest 全量 | 全绿 |
| **回放验证** | L1 胜率 ≥50% 且样本 ≥30 条（`--replay` 后看效果页） |
| 聚宽确认 | 与本地方向一致 |

### 5. 上线观察期

- 先在 settings 启用，跑一周真实信号
- 效果页看 `real` 数据：L1 胜率、L2 收益
- **不达标 → 从 ENABLED_STRATEGIES 移除**（不硬删代码，留档）

## 三、文案与代码一致性（2026-09-09 事故教训）

**事故**：策略页买卖条件文案写了 `MA20<MA60`。裸 `<` 被浏览器当成标签开始符，吞掉后续 `</div>`，导致第一个卡片 div 延伸到页面底部——**色条横跨三个卡片**（用户发现）。

**规范**：

1. 策略页所有文案字段（buy/sell/principle/why/good/bad）**必须 HTML 转义**——已由 `page_strategy` 内的 `_esc()` 统一处理，新增字段务必套用
2. 文案含 `<` `>` `&` 时，跑 `test_strategy_conditions_html_escaped` 防回归
3. 改策略逻辑 → 同步改文案 → 加测试断言文案与代码一致（`test_strategy_sell_conditions_match_code`）
4. **部署后必须用浏览器实际看一次**——curl 抓 HTML 只能验证内容，结构错误（如未闭合标签）只有浏览器解析才暴露

## 四、禁止事项

- ❌ 一次改多个参数
- ❌ 无机制理由的调参
- ❌ 跳过回放对比直接上线
- ❌ 策略文件硬编码参数
- ❌ 改逻辑不同步文案
- ❌ 文案含裸 `<` `>` `&`（必须转义）
- ❌ 只用 curl 验证前端改动（必须浏览器看一眼）

## 六、效果页数据怎么读

| 指标 | 含义 | 健康值 |
|---|---|---|
| L1 胜率（BUY） | 买入信号后 10 日跑赢沪深300 的比例 | ≥50% |
| L1 胜率（SELL） | 卖出信号后跑输的比例（回避下跌） | ≥50% |
| L1 平均超额 | 相对大盘的平均优势（SELL 行已翻转符号，正=好） | >0 |
| L2 胜率 | 完整买卖周期盈利笔数占比 | ≥45%（含止损） |
| L2 平均收益 | 每笔等权收益 | >0 |
| L2 等权累计 | 所有笔数收益之和（相对对比用） | 越大越好 |

**样本 <30 时不要下结论**（当前页面无提示，自行留意）。
