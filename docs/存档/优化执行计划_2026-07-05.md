## 附录：通俗化说明——改了什么东西，对你有什么影响

下面用大白话逐项解释每个修改是干什么的，以及你实际能看到/感受到的变化。

---

### 🔒 安全相关

**1. Token 不再泄露到网上**

> **以前**：钉钉机器人的 key 和 Tushare 的 key 直接写在 `config/settings.py` 里，而这个文件是提交到 Git 的。任何人只要能访问这个 Git 仓库，就能拿到你的 key，往你的钉钉群发消息，或者消耗你的 Tushare API 额度。
>
> **现在**：key 挪到了 `config/settings_local.py`，这个文件加入了 `.gitignore`，永远不会被提交到 Git。同时你已经在钉钉后台轮换了新 key，旧 key 就算被人从 Git 历史里翻出来也没用了。
>
> **你感受到的变化**：无。代码照常运行，推送照常收到。但安全性大幅提升。

---

### 🐛 Bug 修复

**2. 日报在极端情况下不会崩溃了**

> **以前**：如果某天数据源的涨跌幅全部缺失（极少见但可能发生），日报的"市场广度"分析会偷偷崩溃。崩溃被一个空的 `except` 吞掉了，你不会看到任何报错，只是日报里莫名其妙少了这一段。
>
> **现在**：修了一个变量名写错的 Bug，同时加了日志——如果真出了问题，你会看到 `⚠️ [宏观分析]` 的提示。
>
> **你感受到的变化**：日报更稳定，少了一段也不至于完全不知情。

**3. 下载失败的股票不会被误报为"已是最新"**

> **以前**：下载 300 只股票时，如果某只下载失败，它可能被错误地统计为"已是最新"（skip_count），而不是"下载失败"（fail_count）。最终统计告诉你"300 只全部成功"，实际上漏了几只你也不知道。
>
> **现在**：统计逻辑修正，下载失败会如实计入 fail_count。
>
> **你感受到的变化**：每天的下载统计更可信。如果真有问题，会看到准确的失败数量。

**4. 均值回归策略不再刷屏**

> **以前**：如果一只股票持续低于布林带下轨（比如连续暴跌），回归策略会每天都发买入信号，连续 5 天就 5 条。推送消息里同一只股票出现好几次，很烦。
>
> **现在**：改为"仅首次下穿触发"——只在第一天跌破下轨时发信号，后续几天即使还在下轨下方也不再重复发。
>
> **你感受到的变化**：钉钉推送更干净，不会出现同一只股票多次刷屏。

**5. 动量突破卖出信号可以区分强弱了**

> **以前**：所有卖出信号的"强度"都固定为 0.5，不管跌了多少都一样。
>
> **现在**：卖出强度根据跌破幅度动态计算——跌得越多强度越大。这样你可以优先关注那些"跌得特别狠"的股票。
>
> **你感受到的变化**：卖出建议更有层次感，强度高的更值得注意。

---

### ⚡ 性能提升

**6. 多因子选股从 3-5 秒变成瞬间完成**

> **以前**：因子引擎每运行一次，要对 300 只股票各查一次数据库——300 次 SQL 查询，每次都要网络往返，耗时 3-5 秒。
>
> **现在**：改为一次查询全部数据，在内存中用 pandas 分组处理。300 次变 1 次。
>
> **你感受到的变化**：运行 `python -m engine.factor_engine` 时，从"等一下"变成"秒出"。服务器上每天的定时任务也会更快。

---

### 📋 运维改善

**7. 日志系统上线**

> **以前**：所有输出都是 `print()`，cron 定时任务的日志靠 `>> logs/cron.log` 重定向捕获。没有时间戳，不知道哪行是什么时候输出的。
>
> **现在**：引入了专业的 `logging` 模块。日志同时输出到屏幕和文件（`logs/run.log`），每条前面都带时间戳和级别标记：
> ```
> 07-05 02:27:48 [INFO ] run: 信号推送: 成功 | 通过8条 拦截18条 汇总8条
> ```
> 日志文件自动轮转——每个文件最大 10MB，保留最近 7 天。
>
> **你感受到的变化**：出问题时排查更快——打开 `logs/run.log` 就能看到完整的时间线。

**8. 数据库每天自动备份**

> **以前**：`data/stocks.db` 是唯一的，文件损坏则全丢。485K 条日线数据要重新下载才能恢复。
>
> **现在**：新增 `scripts/health_check.py --backup`，每天自动把数据库复制一份到 `data/backups/stocks_日期.db`，保留最近 7 天。
>
> **你感受到的变化**：什么都不用做。把这个脚本加到服务器 cron（21:15）即可自动运行：
> ```bash
> 15 21 * * 1-5 cd /root/Liang-Hua && ./venv/bin/python scripts/health_check.py --backup >> logs/health.log 2>&1
> ```

**9. 崩溃自动告警**

> **以前**：如果 `run.py` 在 21:00 崩溃（网络断、API 变、代码 Bug），你不会收到任何通知。直到第二天手动检查才能发现"昨晚没推信号"。
>
> **现在**：同一个 `health_check.py` 脚本可以检查今天的信号是否正常生成。如果 21:10 还没有当天信号，自动发钉钉告警告诉你"系统可能崩了"。
>
> **你感受到的变化**：加第三条 cron（21:10）即可。系统崩了你会第一时间知道，而不是第二天才发现。

**10. 节假日自动识别**

> **以前**：系统只会判断"是不是周末"，遇到春节、国庆这种 7 天长假，会傻傻地在假期期间运行，推送旧数据。
>
> **现在**：接入了 AKShare 的交易日历——能自动识别所有 A 股休市日，包括春节、国庆、中秋等法定假期。
>
> **你感受到的变化**：长假期间不会收到基于旧数据的推送。日历数据首次加载会慢一点（拉取全年日历），之后有缓存。

### 🏗 代码架构改善

**12. 异常不再静默消失**

> **以前**：项目里到处是 `except Exception: pass`（出了错就当没看见）。这是项目历史上 40% 的 Bug 的根因——Bug 被藏起来数天甚至数周才发现。
>
> **现在**：8 处关键位置的异常都加上了 `⚠️ [模块名] 异常: 具体错误信息`。出了错你能看到。
>
> **你感受到的变化**：以前终端干干净净但功能偷偷挂了；现在终端会明确告诉你哪个模块报了什么错。

**13. 数据库连接不会泄漏**

> **以前**：每次打开数据库连接，如果在使用过程中出异常，连接就永远不关闭。长期运行会累积很多死连接。
>
> **现在**：核心写入路径用 `try/finally` 保护——不管中间成功还是失败，连接一定会关闭。
>
> **你感受到的变化**：无直接感受，但服务器长期运行更稳定。

**14. 代码更整洁——消除了大量重复**

> - 钉钉推送：`dingtalk.py` 和 `dingtalk_report.py` 原本各有一套几乎相同的"发 HTTP 请求"代码（各 20 行）。现在提取到公共模块，两个文件各只留 1 行调用。
> - 因子计算：`factor_engine.py` 和 `local_factor_backtest.py` 原本各自实现了一套因子计算，逻辑不一致。现在统一到 `engine/factors.py`，改了因子逻辑两个地方自动同步。
> - 代理清理：`run.py` 和 `downloader.py` 原本各自清理代理，逻辑重复且不一致。现在统一到一个函数。
